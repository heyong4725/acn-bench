# SPEC 080 — Hypothesis files, falsifier predicates and verdicts

**Status:** Draft v0.1 (September 2026). **Inherits:** SPEC 000, 010; reads SPEC 050 (generator modes), 085 (the loop) and 090 (attribution quantities) where noted. **Prefix:** HYP. **Crate:** `acn-hyp` (frozen set, CON-7). Numbers 17 to 19 and 29 are reserved.
**Purpose:** define the file in which a POC states its hypothesis before it runs, the small typed language in which its falsifier is written, and the only path from bundles to a verdict — such that a negative result cannot be edited into a positive one, by a person or by a loop, without changing a hash that every bundle carries.

## 0. Why a grammar

The report's design rule (Appendix E §E.1) is that hypotheses and falsifiers are fixed before the experiment runs, in a file no automated search loop can edit. That rule has teeth only if the falsifier is *evaluated by a machine*: a falsifier written as free text is re-interpreted every time a result disappoints. This spec therefore fixes a file format that parses strictly (HYP-1..9), a predicate language small enough to specify completely (HYP-10..16), and verdict semantics with no discretionary step (HYP-20..28).

## 1. Definitions

- **Hypothesis file** — one TOML file per POC. **Frozen** when it lives under `hypotheses/`; **candidate** anywhere else, normally `lab/hypotheses/` (CON-17).
- **Arm** — `treatment` or `control`; a session belongs to exactly one (`acn.role`, TRC-10).
- **Cell** — one assignment of values to every `[varies]` parameter. **Slice** — one assignment of values to the *non-pooled* parameters only (HYP-6); a slice contains many cells. **Replicate** — the seeded run with index `i` (CON-27d) of one arm in one cell.
- **Quantity** — a named, documented function (HYP-12) from the view rows of one replicate to a number. Its value for an arm in a cell is the mean over replicates of the per-replicate values; the replicate is the unit of every resampling.
- **Verdict** — `pass`, `fail` or `inconclusive`, with labels.

## 2. File format

**HYP-1** A hypothesis file MUST be TOML and MUST deserialise into the typed structure of this section with unknown keys rejected at every level (`deny_unknown_fields`). A file that does not parse MUST make every command that reads it fail with the key path and the reason; it MUST NOT be partially honoured.

**HYP-2** The file MUST contain the tables `[poc]`, `[hypothesis]`, `[varies]`, `[measures]`, `[control]`, `[design]`, `[falsifier]` and `[expected]`, and no others. `[poc]` MUST carry `id` and `title`; the file stem MUST be `<id>` or `<id>-<slug>`. `[poc]` MAY carry `spec` (the path `specs/<file>.md` of the POC spec; for a frozen file it MUST be present and MUST exist or be listed in `specs/README.md`), `report_refs` (strings: report sections, `H-n` and `G-n` identifiers) and `status`. `[hypothesis]` MUST carry `statement` (a string) and nothing else. `[falsifier]` MUST carry `predicate` and MAY carry `inconclusive_if`, both strings (HYP-10).

**HYP-3** Status is decided by location: a file under `hypotheses/` is `frozen`; a file anywhere else, including a copy inside a kit or a test fixture, is `candidate`. If `[poc].status` is present it MUST equal the status its location implies; a mismatch is a parse error. A `frozen` file's `hypothesis_hash` MUST appear in `env-hash.json`; otherwise the file is treated as `candidate`, so a locally edited copy cannot pass as frozen. Every bundle MUST record the status so determined (`acn.hypothesis.status`, TRC-10).

**HYP-4** Automated agents, search loops and CI jobs MUST NOT hold write access to `hypotheses/` (CON-7 covers the rest of the frozen set). The `acn-hyp` library and the `acn hyp` and `acn loop` subcommands MUST open hypothesis files read-only, MUST NOT write anywhere outside `runs/`, and MUST abort with `hypothesis_changed` if the hash of a hypothesis file changes while a loop is using it (LOOP-13).

**HYP-5** `hypothesis_hash` MUST be computed as CON-27(a) specifies, over the file's bytes. Whitespace and comments are therefore part of the hash, and a frozen file MUST NOT be reformatted. Comments are not normative: where a comment and this spec disagree (for example on how seeds are derived), this spec governs.

**HYP-6** `[varies]` maps each parameter name to exactly one of `{ kind = "bool" }`, `{ kind = "enum", values = [...] }`, `{ kind = "range", min = x, max = y }` (numeric, inclusive) or `{ kind = "int_range", min = a, max = b }`. A `range` or `int_range` MAY carry `levels = [...]`, and MUST carry it when `[design].search = "grid"`. These are the only parameters a loop may vary (LOOP-10); a sample outside the declared domain MUST be rejected before the run starts. A parameter MAY carry `pooled = false`: results are then computed per value of that parameter and never pooled across values (HYP-24). The parameter named `provider` is non-pooled whether or not it says so (CON-26). Enum values MUST be unique across all parameters of a file. Parameter names, enum values and quantity names MUST NOT be reserved words (HYP-10). The value of every parameter for a bundle is read from the manifest's `params` (`vary.<name>`, CON-27b), never inferred from `acn.backend`.

**HYP-7** `[measures]` MUST carry `primary` and MAY carry `secondary`, each a list of quantity names. A predicate MAY reference only quantities listed here. For a frozen file every name MUST resolve to a quantity definition (HYP-12) when the file is loaded; for a candidate an unresolved quantity is a warning, and a verdict that needs it is `inconclusive` (so that a lab idea does not need a change to a frozen crate before it can be written down, CON-23).

**HYP-8** `[control]` MUST carry `description`. A frozen file MUST also carry exactly one of `config` and `workload`; a candidate MAY omit both, and its verdicts are then `inconclusive` (CON-18). `config` is a table assigning values, each within its domain, to some or all pooled parameters; every parameter it does not assign is inherited from the treatment cell. Control runs are keyed by their *effective configuration* (the assigned values plus the inherited ones): there MUST be exactly one control bundle (`arms = "control"`, `vary.*` = the effective values) per distinct effective configuration per slice, and it is the control arm of every treatment cell that maps to it, so that identical control runs are never repeated per cell. `workload` names the generator mode (SPEC 050) that produces a different workload (plain RPC, file transfer) under the same scenario as the treatment (CON-18): it is run once per distinct assignment of the parameters listed in `[control].inherits` (default: every `range` and `int_range` parameter, and any enum parameter the generator mode declares that it reads), and it is the control arm of every treatment cell that agrees with it on those parameters. `q(control)` is per-cell accordingly.

**HYP-9** `[design]` MUST carry `search` (`grid`|`bisect`|`random`), `replicates` (integer ≥ 4, even) and `twin_required` (bool; `false` is permitted only for network-free hypotheses, LOOP-4), and MAY carry `seeds` (only the value `"derived"`, meaning CON-27d) and `seed` (an unsigned 64-bit run seed). When `seed` is absent the run seed of a frozen hypothesis MUST be the first 8 bytes, little-endian, of `blake3("acn-bench/hypothesis_seed/v1\0" ‖ hypothesis_hash)`, so that a loop cannot re-run a frozen hypothesis under fresh seeds until it passes; a verdict MUST refuse frozen-hypothesis bundles run under any other seed. `[design]` MAY also carry `backends` (a list drawn from `"mockllm"` and `"real-api"`, the two ways of providing inference; which real providers run is the `provider` parameter), `min_providers_for_verdict` (integer, default 1; meaningful only when the file has a `provider` parameter) and `sim_live_tolerance` (a table from `[measures]` quantity names to a relative tolerance, CON-25; a quantity not listed is unconstrained). `[expected]` MUST carry `outcome` (`pass`|`fail`) and MAY carry `note`; it is recorded in the verdict and MUST NOT affect it.

## 3. The predicate language

**HYP-10** `[falsifier].predicate` and `[falsifier].inconclusive_if` are strings in the language below and MUST be parsed and type-checked when the file is loaded; one that fails makes the file fail to load. The falsifier evaluates to a boolean: **true means the hypothesis is refuted**. Reserved words are `and`, `or`, `not`, `at`, `all`, `any`, `control`, `treatment`, `ci`, `true`, `false`, the counters `replicates` and `providers_reported`, and the built-in names of HYP-13. A parser needs two tokens of lookahead to tell `ident "="` from an expression that starts with an identifier, and in a `barg` the built-in's signature (HYP-13) selects the alternative: where it expects a quantity reference the argument MUST be a bare `qname`. Numbers carry no sign, so the bound of an `at` clause and a `ci` value are non-negative; `ci` MUST lie strictly between 0 and 1.

```
expr     := or ( "at" ( "all" | "any" ) pname cmpop number )?
or       := and ( "or" and )*
and      := not ( "and" not )*
not      := "not" not | cmp
cmp      := sum ( cmpop sum )?
cmpop    := "<" | "<=" | ">" | ">=" | "==" | "!="
sum      := term ( ( "+" | "-" ) term )*
term     := unary ( ( "*" | "/" ) unary )*
unary    := "-" unary | atom
atom     := number | builtin | select | counter | qname | "(" expr ")"
select   := qname "(" selector ( "," selector )* ")"
selector := "control" | "treatment" | pname "=" value | evalue
builtin  := fname "(" barg ( "," barg )* ")"
barg     := "ci" "=" number | "control" | "treatment" | qname | expr
counter  := "replicates" | "providers_reported"
qname    := a name listed in [measures]
pname    := a parameter of [varies]
value    := evalue | "true" | "false" | number
evalue   := an enum value of [varies]
fname    := one of the built-ins of HYP-13
number   := [0-9]+ ( "." [0-9]+ )? ( ( "e" | "E" ) ( "+" | "-" )? [0-9]+ )?
ident    := [a-z_][a-z0-9_]*          (qname, pname, enum values and fname are idents)
```

The `at` clause has the lowest precedence and applies to the whole predicate, so `A or B at all x <= 1` means `(A or B) at all x <= 1`. An identifier followed by `(` is a `builtin` when it is one of the names of HYP-13 and otherwise MUST be a `qname`, which makes it a `select`; any other name is an error.

**HYP-11** The language MUST be statically typed with three types: *number*, *boolean* and *quantity reference* (a `qname` given to a built-in that expects one). There is no implicit conversion. Comparison takes numbers and yields a boolean; `and`, `or`, `not` take booleans; arithmetic takes numbers. A value is *undefined* when it has no data: no completed replicates, a division by zero, an unresolved quantity (HYP-7). Undefined MUST propagate strictly through arithmetic, comparison, `and`, `or`, `not`, `at all`, `at any` and every built-in: if any operand, or any cell a construct ranges over, is undefined, the result is undefined. An undefined falsifier yields `inconclusive` with the reason recorded, never `pass` or `fail`.

**HYP-12** Names MUST resolve as follows. A bare `qname` is the quantity's value in the treatment arm of the current cell. In a `select`, `control` and `treatment` choose the arm, `pname = value` fixes a parameter, and a bare `value` fixes the one parameter that declares it (values are unique across parameters, HYP-6); a parameter fixed by a selector is excluded from the cells an `at` clause or an aggregate ranges over. A bare value selector MUST be an enum value; a bool or a number is written `pname = value`. A parameter that one `select` of a predicate fixes MUST be fixed, to some value, in every other `select` of that predicate that does not choose `control`. `q(control)` is the control arm the cell maps to (HYP-8). A selector MUST NOT fix a non-pooled parameter: inside a per-value verdict (HYP-24) only one value exists. The counter `replicates` is, within a slice, the minimum over the arms of the evaluated cells of the number of completed replicates with index in `0..[design].replicates`; at file level it is the minimum of that value over the slices counted in `providers_reported` (over all slices when the file has no `provider` parameter). The counter `providers_reported` is defined at file level by HYP-24; inside a slice it equals the number of values the `provider` parameter declares, so that a guard written on it never fires there, whatever its polarity. Quantities MUST be defined in one table in `acn-hyp`: name, unit, a documented formula over named view columns and `acn.*` promoted columns only (TRC-3), and any named constants it needs (for example the per-provider price table behind `cost_per_success`, which lives in the frozen set and so moves `env_hash`); attribution quantities such as `network_attributable_share` are defined by SPEC 090 and registered here by name. The table MUST be rendered by `cargo xtask docs-inventory`.

**HYP-13** The built-ins MUST be exactly these, and an unknown `fname` is an error. Over numbers: `abs(x)`, `min(x, y)`, `max(x, y)`. Taking a quantity reference `q` and evaluated per cell: `effect(q)` = `q(treatment) − q(control)`; `rel_effect(q)` = `effect(q) / q(control)`; `ci_low(q, ci = 0.95)` and `ci_high(q, ci = 0.95)`, the bounds of the percentile-bootstrap confidence interval of `effect(q)` (HYP-15). Aggregates over the evaluated cells of the current slice, each yielding one slice-level number: `max_over_knobs(x)` and `min_over_knobs(x)`. Slice-level by definition: `noise_floor(q, control, ci = 0.95)`, computed for each control bundle of the slice (there is exactly one per distinct effective configuration, HYP-8, so "the control replicates" is never a pool across cells) as half the width of the percentile-bootstrap confidence interval of `stat(even) − stat(odd)`, where *even* and *odd* are the control replicates with even and odd index among `0..replicates` and `stat` is the mean of the per-replicate values, and then taken as the **largest** such value in the slice (the conservative choice: it makes a small effect harder to call real). The arguments `control` and `treatment` are accepted only where listed here.

**HYP-14** Every sub-expression is either *per-cell* (it mentions a bare `qname`, a `select` that leaves pooled parameters free, or a per-cell built-in) or *slice-level* (numbers, counters, aggregates, `noise_floor`, and a `select` that fixes every pooled parameter). A per-cell predicate MUST carry an `at` clause, or be wrapped in aggregates, whenever the design has more than one cell in a slice; otherwise the file MUST be rejected as ambiguous. `P at all v <= c` holds when `P` holds in every evaluated cell of the slice whose parameter `v` satisfies the bound, and `at any` when it holds in at least one; with no such cell the result is undefined. Cells are ordered by parameter name, then by value: numerically for numbers, `false` before `true`, and in declaration order for enum values.

**HYP-15** Evaluation MUST be deterministic. Bundles are processed in ascending `run_id` order whatever the argument order. The verdict seed is the first 8 bytes, little-endian, of `blake3("acn-bench/verdict/v1\0" ‖ hypothesis_hash ‖ run_ids)`, with the run IDs as raw digests in ascending order. `verdict_id = blake3("acn-bench/verdict_id/v1\0" ‖ hypothesis_hash ‖ run_ids)` over the same fields. Every bootstrap uses `B = 10 000` resamples of replicates, drawn from its own sub-stream `hyp.bootstrap/<slice key>/<cell key>/<quantity>/<function>` derived from the verdict seed as in CON-27(c), so that no draw depends on evaluation order. A key is its `name=value` pairs sorted by name and joined by `,`, with values in the string forms of CON-27(b); the slice key is empty for a file with one slice; for `noise_floor` the cell key is the control's effective configuration. `<function>` is `effect` for `effect`, `rel_effect`, `ci_low` and `ci_high` alike, so that both bounds of an interval come from one set of resamples, and `noise_floor` for `noise_floor`. For `effect`, treatment and control are resampled **as pairs by replicate index** (the arms share `replicate_seed(i)`, and HYP-21 has already required every index in both). With the `B` resampled values sorted ascending and indexed from zero, the lower bound is the value at index `floor(B·(1−ci)/2)` and the upper bound the value at index `ceil(B·(1+ci)/2) − 1`. Sums run in replicate-index order. `verdict.json` MUST have sorted keys and shortest-round-trip floats. The same bundles and the same hypothesis file MUST yield a byte-identical `verdict.json`.

**HYP-16** When this spec is accepted, the predicates of the two existing files MUST load under it unchanged: `hypotheses/p4.toml` — `max_over_knobs(abs(effect(cost_per_success))) < noise_floor(cost_per_success, control, ci = 0.95)`, a comparison of two slice-level numbers, with `inconclusive_if = "replicates < 20 or providers_reported < 2"` — and `lab/hypotheses/p17-a2a.toml` — `network_attributable_share(a2a) - network_attributable_share(control) < 0.05 at all rtt_ms <= 150`, two `select`s, the first fixing `protocol` by its unique value `a2a`. Both files also satisfy §2 as they stand (`p17` by the `<id>-<slug>` stem rule and the candidate allowances of HYP-7 and HYP-8). An implementer who finds that a file needs an edit to conform MUST report it to the owner and MUST NOT edit the file (CON-7).

## 4. Verdicts

**HYP-20** `acn hyp verdict --hypothesis <file> <bundle>…` MUST be the only path from bundles to a verdict (CON-17). It MUST verify each bundle (TRC-23), MUST refuse bundles whose `hypothesis.hash` differs from the file's, MUST refuse a set whose bundles disagree on `env_hash` or whose `env_hash` differs from the tool's own, MUST refuse a set in which two bundles cover the same slice, cell, arm, mode and replicate index, MUST refuse a set that mixes `mockllm` and real backends, MUST refuse to overwrite an existing verdict directory, MUST write `runs/verdicts/<verdict_id>/verdict.json` (HYP-15) and MUST print the same object (CON-8). Verdicts are not part of any bundle (TRC-22).

**HYP-21** The verdict of one slice MUST be computed by these rules and nothing else. If the set contains sim bundles, quantities and replicate counts come from the sim bundles only, and live bundles are read only by the twin rule (HYP-22); if it contains only live or only netem bundles, they come from those. Only replicate indices `0..[design].replicates` are read; bundles with a higher index are *ignored* and listed in `reasons`, so that running until a result looks good changes nothing. A replicate is *completed* when its bundle verifies and its sessions ended. The verdict is `inconclusive` if, in order: the control arm is missing (CON-18); any arm of any evaluated cell has fewer completed replicates than `[design].replicates`; for `search = "grid"`, any cell of the grid has no runs; `inconclusive_if` is true or undefined; the falsifier is undefined; or the twin rule of HYP-22 fails. Otherwise it is `fail` if the falsifier is true and `pass` if it is false. `reasons[]` MUST list every cause that applied, in the order above.

**HYP-22** Twin rule (CON-25). `acn hyp verdict` MUST compute sim↔live divergence itself, from sim and live bundles paired by cell, arm and replicate index. For each quantity in `[design].sim_live_tolerance`, the divergence of a cell and arm is `|mean_live − mean_sim| / |mean_sim|` over the replicate indices present in both modes, and the cell's divergence is the larger of its arms'; `mean_sim = 0` makes it undefined. The replicate-count check of HYP-21 does not apply to live bundles, which LOOP-12 produces only for the decision-relevant cells. When `twin_required` is true, a cell that has live bundles and whose divergence exceeds a tolerance, or is undefined, makes the verdict `inconclusive`. A verdict computed with no live bundle at all is evaluated normally and labelled `sim-only`; this is what the loop runner uses at L1 (LOOP-10), and LOOP-12 then twins the decision-relevant cells.

**HYP-23** Labels: `exploratory` when the file is a candidate **or any bundle's manifest records `hypothesis.status = "candidate"`**, so that a candidate's runs cannot become evidence by moving the file afterwards; `mock-gated` when any bundle has `backend = "mockllm"` (CON-26); `sim-only` when no live bundle was evaluated. A verdict carrying `exploratory` or `mock-gated`, or carrying `sim-only` while `twin_required` is true, MUST NOT be rendered as citable on an evidence page (LOOP-30).

**HYP-24** Non-pooled parameters split the evaluation: there MUST be one slice verdict per combination of their values (for `provider`, one per provider), reported side by side; inside a slice the counters take the values HYP-12 gives them. The file-level verdict is then computed once: `providers_reported` is the number of provider values whose slice verdict is not `inconclusive` and not `mock-gated`; `inconclusive_if` is evaluated again at file level with the file-level counters; the file-level verdict is `inconclusive` if that is true or undefined, or, for a file that has a `provider` parameter, if `providers_reported < [design].min_providers_for_verdict`, `fail` if any slice verdict is `fail`, and `pass` otherwise. A file with no non-pooled parameter has one slice, and its verdict is the file-level verdict.

**HYP-25** A `fail` on a frozen hypothesis is a result. Tooling MUST NOT offer an option to relax, rewrite or re-scope the hypothesis, and MUST record a `fail` on the evidence page like any other verdict (LOOP-3).

**HYP-26** Freezing: a candidate becomes frozen by a Class C PR that moves the file to `hypotheses/`, removes or corrects `[poc].status`, adds its POC spec, and updates `env-hash.json`. The PR MUST precede the first run whose bundle is cited (CON-17). `cargo xtask env-hash --check` failing on a changed hypothesis file is the freeze check.

**HYP-27** `acn hyp lint <file>` MUST parse a hypothesis file, type-check its predicates, resolve its quantities and print the parsed structure and warnings, without reading any bundle. CI MUST run it on every file under `hypotheses/`, where a failure fails the build. On files under `lab/hypotheses/` it is advisory: the result is reported and MUST NOT fail the build (CON-23).

**HYP-28** `verdict.json` MUST carry: `verdict_id`, `verdict`, `reasons[]`, `slices[]` (each with its parameter values, verdict, reasons and labels), `hypothesis {id, status, hash}`, `expected`, `labels[]`, the `run_id` of every bundle read and of every bundle ignored (HYP-21: a replicate index at or beyond `[design].replicates`), `env_hash`, every distinct `build_hash`, the value of every quantity and sub-expression the predicates evaluated (per slice, cell and arm, with replicate counts and confidence intervals), the twin divergences, and the treatment-minus-control effect of every primary quantity (CON-18).

## 5. Acceptance tests (names are normative)

- `crates/acn-hyp/tests/format.rs` — HYP-1..3, HYP-5..9: strict parsing, unknown keys, the stem rule, status by location and by `env-hash.json`, domains, reserved words, candidate allowances, control forms.
- `crates/acn-hyp/tests/predicate_parse.rs` — HYP-10, HYP-11, HYP-13, HYP-14: grammar and precedence of `at`, the three types, unknown functions, per-cell versus slice-level, ambiguity rejection; golden parse trees.
- `crates/acn-hyp/tests/quantities.rs` — HYP-12: selectors, unique enum values, the quantity table and its rendering, per-replicate-then-mean.
- `crates/acn-hyp/tests/existing_files.rs` — HYP-16: `p4.toml` and `p17-a2a.toml` load unedited, with the parse trees this spec describes.
- `crates/acn-hyp/tests/verdict_semantics.rs` — HYP-20..24, HYP-28: each `inconclusive` cause in order, extra replicates ignored, the missing grid cell, strict undefined propagation, labels including the back-dated freeze, the twin rule, per-provider slices and the two-pass `providers_reported`; on synthetic bundles.
- `crates/acn-hyp/tests/verdict_determinism.rs` — HYP-15: byte-identical `verdict.json` across two evaluations and across argument orders; `noise_floor` halves.
- `crates/acn-hyp/tests/readonly.rs` — HYP-4, HYP-25: a hypothesis directory made writable is never written; a changed file aborts the loop; no relax option exists.
- `crates/acn-hyp/tests/freeze.rs` — HYP-26: the freeze PR shape is what `env-hash --check` and `pr-check` enforce.
- `tests/accept/hyp_lint.rs` — HYP-27: every frozen file lints clean; a broken candidate is reported without failing.

## 6. Open questions (ADR candidates)

1. Whether `noise_floor` should stay the split-half control statistic defined here or become a paired A/A run. With many cells, a maximum over cells compared with a single split-half floor is statistically weak; SPEC 100 should say whether POC 4 needs a multiplicity correction, as a new built-in rather than a change to this one.
2. Whether `bisect` designs need a `crossing(q, threshold)` built-in so a boundary-finding falsifier (POC 1a, POC 7) can state "no crossing exists" directly, and what minimum coverage an `at all` over adaptively chosen cells requires.
3. Whether per-value verdicts (HYP-24) should generalise beyond `provider` to endpoint class in POC 1a.
4. The owner may wish to tidy two things in the existing files while it is cheap: the seeds comment in `hypotheses/p4.toml` shows an un-prefixed formula that CON-27(d) supersedes, and `provider` could say `pooled = false` explicitly.
5. LOOP-10 stops a loop "when the falsifier's confidence interval no longer straddles its threshold". A falsifier here is a boolean, and HYP-21 reads a fixed replicate set, so that stop rule needs restating in SPEC 085 in terms this spec defines (for example: every cell has its `replicates`, or the budget is spent). That is a follow-up `spec-change`, not part of this one.
